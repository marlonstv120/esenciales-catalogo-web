# Contexto actual

- **Plan de cierre:** Bloques 0, 2, 3, 4 y 6 están implementados. `20260930000100`, `20260930000200`, `20261001000100` y `20261001000200` están aplicadas local y remotamente. `/carrito` registra solicitudes con revisión explícita de precio, confirmación no personal y WhatsApp voluntario. La administración lista solicitudes, corrige Nuevas y permite confirmar, entregar o cancelar con RPC administrativas transaccionales e inventario; falta validación manual integral y E2E remoto con datos controlados.
- **Fase:** catálogo público con cuadrícula unificada, filtros URL de categoría, disponibilidad, género, clasificación y precio, ordenamiento, selector de presentaciones y carrito local. El carrito permite seleccionar las líneas que se registran, ajustar cantidades con controles `− / +` y recibe avisos flotantes al agregar desde catálogo o detalle. Queda pendiente la validación manual visual, de teclado y responsive.
- **Último hito:** Bloque 6 aplicado al remoto: `#solicitudes` permite confirmar o cancelar una Nueva y entregar o cancelar una Confirmada; bloquea transiciones con cambios de edición sin guardar. `npm run test:auth` pasó con 116 pruebas, `npx supabase test db` pasó con 238 pruebas, `npm run build` pasó y `npm run supabase:status` confirmó `20261001000200` alineada en local/remoto el 30 de septiembre de 2026. La suite remota completa conserva fallos previos por datos persistidos, incluida la categoría `prueba`, que no se modificó.
- **Documento rector:** `docs/project/functional-scope.md`, complementado por requisitos, reglas de negocio y flujos en `docs/project/`.
- **Decisiones vigentes:** MVP exclusivo para Esenciales; ocho macrofuncionalidades; solicitudes de compra con pago manual Bre-B opcional para casos elegibles; catálogo público; administración de inventario por presentación; WhatsApp como continuación voluntaria; PostgreSQL confirmado.
- **Decisiones recientes:** el título formal termina en `para la empresa ESENCIALES`; el informe escribe `ESENCIALES` en mayúsculas y la presenta como empresa; el briefing validado se conserva como línea base histórica; una ampliación posterior incorpora pago manual opcional por Bre-B para solicitudes elegibles, con QR/llave del negocio, comprobante privado y verificación administrativa transaccional, sin pasarela ni validación bancaria automática; una solicitud Nueva no descuenta ni reserva inventario; dirección y barrio se recopilan por WhatsApp; costos internos, módulo de clientes, cuentas por cobrar y reportes de ventas quedan fuera del MVP; Productos destacados mediante selección manual; agotado derivado del stock; Bajo pedido con stock vendible cero; precios COP enteros; solicitudes Nuevas permiten corregir cliente, cantidades o retirar líneas, sin agregar líneas ni cambiar presentaciones o precios; solicitudes Confirmadas inmutables; el administrador tendrá recuperación de contraseña por correo; cada solicitud exige aceptación de términos y política de datos y conserva sus versiones y fecha; no se incluyen comunicaciones promocionales.
