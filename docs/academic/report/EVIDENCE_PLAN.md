## Criterios de presentación

- El comparativo principal enfrenta el proceso inicial de gestión y presentación del catálogo con el proceso apoyado por la aplicación; no presenta Excel o WhatsApp como una versión anterior del sistema.
- La entrevista conserva un registro sintetizado de las respuestas, no una transcripción literal, y el briefing resume la línea base validada de necesidades y requisitos. En resultados se compara con las funcionalidades efectivamente implementadas y validadas.
- El comparativo visual de diseño utiliza una evidencia preliminar real, como boceto, wireframe o primera interfaz, y una captura equivalente de la versión final.
- El código QR de la sustentación apunta a la URL pública estable y se acompaña con el enlace escrito por si la lectura del código falla.
- El QR de acceso de la sustentación y el QR de pago Bre-B tienen propósitos diferentes: el primero abre la aplicación publicada y el segundo contiene instrucciones bancarias proporcionadas por el negocio. No deben confundirse en las evidencias.
- El pago Bre-B se presenta como transferencia externa con comprobante y revisión manual, no como pasarela, cobro automático o venta concluida sin validación administrativa.
- La entrevista completa se conserva como fuente o anexo. El cuerpo del informe presenta únicamente el procedimiento y la síntesis de los hallazgos relevantes; el briefing sirve como documento breve de validación con el propietario.
